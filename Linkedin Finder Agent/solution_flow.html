LinkedIn Contact Finder Agent — Solution Flow Architecture

Autonomous State-Graph Pipeline · SerpAPI Google AI Overviews · BrightData MCP Web Scraper · Azure OpenAI Structured Outputs

Solution Flow Overview

The Contact Finder Agent uses a sequential, state-machine pipeline constructed with LangGraph. It initializes state with target company metadata, generates an optimal Google search query via Azure OpenAI, extracts initial AI Overviews from SerpAPI, and enters an autonomous MCP research loop to discover decision makers.

Guardrails & Compliance

To prevent infinite loops and guarantee policy compliance, the research loop enforces strict exit criteria: a maximum budget of 10 web scraping calls, a cap of 5 decision makers, and an explicit rule blocking the scraping of personal LinkedIn profile URLs.

Persistence & Export Formats

All state transitions are persisted in real-time to SQLite (memory.db) via AsyncSqliteSaver. Upon completion, verified decision makers are written to an Excel sheet (contacts_{session}.xlsx) and full state history is saved to JSON (agent_state_{session}.json).
